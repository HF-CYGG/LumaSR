# LumaSR v0.3.2 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Repository instructions forbid subagents and Git worktrees unless the user explicitly authorizes them.

**Goal:** 将当前 GitHub 更新检查功能发布为 `v0.3.2`，生成固定证书签名且符合客户端更新规则的 `LumaSR.apk`，并在本地合并到 `main`。

**Architecture:** `app/build.gradle.kts` 提供唯一应用版本；PowerShell 元数据校验脚本约束数字版本标签、版本号和发布说明；固定签名构建脚本生成按标签分目录的规范资产、SHA-256 与发布清单；GitHub 发布脚本默认只验证，只有显式 `-Publish` 才调用 `gh release create`。GitHub Actions 只校验标签契约，不接触私钥或构建大型 APK。

**Tech Stack:** Android Gradle Plugin、Kotlin/JUnit 4、PowerShell 5.1、Android SDK `apksigner`/`aapt2`/`zipalign`、GitHub CLI、GitHub Actions。

## Global Constraints

- `versionName = "0.3.2"`，`versionCode = 3`。
- 正式标签必须是 `v0.3.2`；未来继续使用客户端支持的 2–4 段纯数字 `vX.Y[.Z[.N]]`。
- GitHub Release 只能上传一个规范 APK 资产，文件名固定为 `LumaSR.apk`。
- Release 必须是正式、非草稿、非预发布版本；不得复用或覆盖旧标签。
- APK 必须延续证书 SHA-256 `43648398DD74C72B1CBA185D3832E558C72D9BB58AE46BB9C09EF32818988D2F`。
- 不记录、提交或输出 keystore、密码和 Token；不新增生产依赖。
- 只在本地合并和打标签，不推送、不创建线上 GitHub Release。
