# 性能校准进度与控制台卡片设计

## 目标

本机性能校准开始后，使用模态卡片持续展示真实执行步骤、总进度、已用时间、预计剩余时间和完整校准日志。校准结束或失败后保留最终状态与日志，直到用户主动点击“完成”。

## 交互

- 从首次提示或设置页启动校准后，关闭原入口提示并立即显示校准卡片。
- 运行中卡片不可通过返回键或点击遮罩误关闭，也不提供会留下后台任务的伪取消按钮。
- 卡片顶部依次显示状态标题、`步骤 N/M`、当前步骤名称、线性进度条、已用时间和预计剩余时间。
- 第一个真实探针完成前显示“预计剩余：正在估算”；之后根据已完成的实际耗时和剩余工作量动态更新。
- 下方控制台区域使用深色背景和等宽字体，按事件追加日志并自动滚动到最新一行。
- 成功、失败或超时后停止计时，保留完整日志、总耗时和结果摘要，并显示“完成”按钮。只有用户点击按钮后关闭卡片。

## 真实事件来源

`InferenceCalibrationRunner` 在实际操作边界发送结构化事件，不解析 Logcat，也不生成与执行无关的动画日志：

- 校准计划建立；
- FP32/FP16 质量探针开始和完成；
- SMALL、STANDARD、LARGE 的 Vulkan 安全参考、FP16 候选和 CPU 基线开始与完成；
- TTA 质量与速度探针（模型支持时）；
- 质量门判断、每档最终参数选择、benchmark 原子发布；
- 探针失败、资源不足、温度中止、超时和最终结果。

每个探针日志包含实际后端、精度、分辨率、tile、batch、CPU 控制值、输出尺寸和实测耗时中适用的字段。不得记录模型目录、图片路径、临时文件路径或设备隐私数据。

## 状态与 ETA

- 新增不可变的校准进度事件和 UI 快照；`DeviceCalibrationCoordinator.run()` 接受进度回调，并由 Runner 逐事件上报。
- Runner 在开始时根据候选预算、分辨率档位和 TTA 能力计算计划步骤数与工作量。
- 工作量以输出像素为基础，CPU 和 TTA 使用保守倍率；每完成一个真实探针，用累计实际耗时除以累计工作量估算剩余时间。
- ETA 始终钳制到非负值和剩余的五分钟总预算内。事件异常、零耗时或尚无完成工作量时显示“正在估算”，不显示虚假数字。
- `LumaViewModel` 保存当前会话的全部日志并每秒刷新显示时间；进程重启后不恢复一次未完成会话的控制台日志，benchmark 的原子发布语义保持不变。

## Compose 结构

- 新增独立 `CalibrationProgressDialog`，只接收不可变 UI 状态和完成回调，不直接持有 ViewModel。
- 使用 Material 3 `Dialog`/`Surface`、明确的进度语义和可选择的等宽日志文本。
- 日志区域有固定最大高度并独立滚动，卡片在小屏幕和横屏下不超出安全边界。
- 卡片位于根界面层，因此用户从设置页或首次提示启动时行为一致，校准期间也不会被底部导航覆盖。

## 错误与完成行为

- 失败、超时和不支持设备使用不同结果标题，并在日志末尾追加真实原因的安全文案。
- Runner 或进度回调异常不得破坏校准主流程；UI 回调只更新内存状态。
- 完成按钮仅在终态可用。关闭后保留现有 `CalibrationUiStatus` 和顶部结果通知，不保留卡片会话。

## 测试与验证

- Runner 单测验证生产候选路径的事件顺序、实际参数、耗时、档位选择、发布和失败终态。
- 纯 Kotlin reducer 单测验证日志完整追加、步骤推进、ETA 估算/钳制、计时停止和终态保留。
- ViewModel/架构测试验证开始时显示卡片、完成后不自动关闭、点击完成后清除会话。
- Compose 静态和真机检查验证顶部步骤、ETA、控制台滚动、返回键拦截、成功与失败终态。
- 最终运行全量 JVM 测试、`lintDebug`、Debug/Release 构建和固定签名验签；真机只声明本次连接设备的实际证据。

## 固定约束

- 不新增依赖，不改变模型、校准候选、五分钟超时、benchmark schema、原子发布、`minSdk`、权限或固定 APK 签名。
- 不解析 Logcat 作为产品状态来源，不记录图片或文件路径，不声明未实测 OEM 兼容性。
